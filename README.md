# Savvy

Desktop-приложение на Electron для постановки ссылок в очередь и скачивания через локально установленный [yt-dlp](https://github.com/yt-dlp/yt-dlp).

## Требования

- Node.js 24 или новее;
- npm;
- `yt-dlp` уже входит в установочный пакет;
- `ffmpeg` нужен для объединения отдельных потоков видео и аудио;
- `deno` — опционально, для JavaScript runtime yt-dlp.

Пути к бинарникам ищутся при запуске и по кнопке «Найти yt-dlp» в `PATH`, системных каталогах и `~/.local/bin`; найденные варианты показываются с версией и путём, но не выбираются автоматически. В packaged-приложении также проверяется каталог `resources/bin`.

Если yt-dlp не найден, настройки предлагают установить официальный standalone-бинарник stable или nightly в каталог данных приложения `userData/bin`. Перед заменой Savvy сверяет SHA-256 с опубликованным файлом `SHA2-256SUMS`; при ошибке текущий бинарник остаётся без изменений. Выбранный файл имеет приоритет над поиском. Для управляемого приложением файла кнопка обновления повторно скачивает выбранный канал с проверкой checksum; для внешнего release-бинарника используется `yt-dlp -U`. Homebrew, pip, pipx и другие пакетные менеджеры Savvy не запускает.

Кнопка «Проверить последнюю версию» показывает опубликованный `tag_name` выбранного канала stable или nightly и не запускает установку либо обновление.

## Установка и запуск

```bash
npm ci
npm run dev
```

Для production-сборки:

```bash
npm run build
npm run dist:linux
npm run dist:mac
npm run dist:windows
```

### Установка из DMG на macOS

Сборка не подписана сертификатом Apple Developer Program, поэтому Gatekeeper
может показать «Savvy повреждён и не может быть открыт» или «Не удаётся
проверить разработчика». Приложение при этом рабочее — блокирует его карантинная
метка. Варианты обхода:

```bash
xattr -cr /Applications/Savvy.app
```

Либо после переноса `Savvy.app` в `/Applications` открыть
«Системные настройки → Конфиденциальность и безопасность» и нажать
«Открыть всё равно». Правый клик → «Открыть» может не сработать для
неподписанных сборок — используйте `xattr`.

## Релизы

Раз в неделю (по понедельникам, 09:00 по Москве) workflow проверяет `master`.
Если после последнего релиза есть изменения, публикуется alpha-релиз:
`1.2.3-alpha.1`, `1.2.3-alpha.2` и так далее. Без изменений релиз не выходит. До стабильного релиза меняется
только номер alpha. Стабильный релиз запускается вручную через
`Actions → Release → Run workflow` и публикуется без суффикса, например
`1.2.3`. После него следующий alpha-цикл начинается с версии `1.2.4-alpha.1`.

```bash
git switch master
git pull --ff-only
git push origin master
```

Текущая версия проекта — `0.0.1-alpha.3`. CHANGELOG обновляется через
`conventional-changelog`, а Release Notes формируются по Conventional Commits.

### Автообновление приложения

Установленные alpha-сборки проверяют GitHub Releases при запуске и затем каждые
12 часов, пока приложение запущено. Когда доступна новая версия, в верхней
панели появляется иконка: цвет и индикатор показывают этап (найдено, скачивается,
скачано, ошибка). При наведении видны версии и краткий список изменений. Клик по
иконке скачивает обновление, а после загрузки предлагает установить его с
перезапуском; перед установкой Savvy предупреждает о выполняющихся и ожидающих
загрузках. Если обновление скачано, но не установлено, оно ставится при
следующем выходе из приложения.

В настройках, в секции «Обновление приложения», доступны ручная проверка, полный
список изменений, повтор скачивания и ссылка на GitHub Release. Windows и
AppImage обновляются через `electron-updater`; для `.deb` и macOS открывается
страница релиза, потому что сборка macOS не подписана Developer ID. После
появления подписи включите `MAC_AUTO_UPDATE_ENABLED` в
`src/main/application-update-capabilities.ts` и добавьте GitHub secrets
`CSC_LINK`, `CSC_KEY_PASSWORD`, `APPLE_ID`, `APPLE_APP_SPECIFIC_PASSWORD` и
`APPLE_TEAM_ID`. Workflow передаёт их только macOS-сборке.

Отдельный CI запускает проверки качества и тесты для `master`, а также для
pull request в эту ветку.

Нумерация определяется по Git-тегам: стабильный тег `v1.2.3` задаёт следующую
alpha-основу `1.2.4`, а alpha-теги `v1.2.4-alpha.N` увеличивают только `N`.

## Архитектура

- `src/main` — Electron main-процесс и NestJS application context;
- `src/main/modules` — модули по зонам ответственности: загрузки, настройки, shell, поиск бинарников;
- `src/main/services` — доменная логика очереди, настроек и системных диалогов;
- `src/preload` — типизированный безопасный IPC API через `contextBridge`;
- `src/renderer` — интерфейс очереди и настроек;
- `src/shared` — общие типы main/preload/renderer.

Renderer не получает прямого доступа к Node.js: окно работает с `contextIsolation: true` и `nodeIntegration: false`.

## Возможности

- очередь скачиваний с прогрессом, логом, повтором и историей;
- ограничение числа параллельных загрузок;
- UI- и текстовый режимы настройки yt-dlp;
- выбор системного бинарника yt-dlp, отображение его версии и обновление release-бинарника;
- импорт config-файлов и предпросмотр итоговых аргументов;
- светлая и тёмная тема с сохранением выбора между запусками;
- понятные рекомендации по настройке cookies, частоты запросов, сети и yt-dlp при HTTP 403.

Перед скачиванием Savvy формирует единый config-файл yt-dlp: текст из режима «Текстом» дополняется параметрами UI, причём UI-параметры имеют приоритет при совпадении.

Настройки и история хранятся в каталоге `app.getPath('userData')` текущей операционной системы.

## Разработка

Изменения в проекте должны соответствовать строгому TypeScript, ESLint и Prettier. Новую функциональность следует сначала покрыть тестом, затем реализовать и проверить командами из раздела «Проверки качества».
