# HTTP 403 в yt-dlp: диагностика и разрешённые действия

Этот документ — основа для подсказок Savvy при `HTTP Error 403: Forbidden`.
`403` означает отказ конкретного сервиса, а не единый тип сбоя yt-dlp. До
повторной попытки приложение должно сохранить в консоли домен запроса, этап
(`extract` или `download`), выбранный бинарник и его версию, URL без секретов
и фактический снимок конфигурации. Для ручной диагностики подходят `-v`
(`--verbose`) и, при необходимости, `--print-traffic`; yt-dlp документирует их
именно как средства отладки. [README yt-dlp: verbosity](https://github.com/yt-dlp/yt-dlp#verbosity-and-simulation-options)

## Порядок диагностики

1. **Определить, где получен 403.** Если он случился при извлечении страницы,
   вероятны устаревший extractor, вход, антибот-проверка или несовместимый
   клиент. Если при загрузке уже выбранного формата — вероятнее временная
   подписанная ссылка, ограничение IP/частоты или сетевой маршрут. Это рабочая
   гипотеза, а не основание бесконечно повторять запрос: UI должен показывать
   исходный stderr и домен.
2. **Сначала проверить версию.** Актуальный `stable` может отставать и ломаться
   после изменений на стороне сайтов; разработчики yt-dlp рекомендуют
   `nightly` для регулярных пользователей и требуют обновить его перед новым
   баг-репортом. `yt-dlp -U` применим только к release-бинарникам, а pip и
   другие менеджеры обновляются тем же способом, которым были установлены.
   [README yt-dlp: update](https://github.com/yt-dlp/yt-dlp#update)
3. **Не применять все варианты одновременно.** Каждая повторная попытка должна
   добавлять ровно одну явно показанную настройку и сохранять результат. Иначе
   невозможно понять причину, а лишние запросы могут усилить ограничение.

## Допустимые варианты по причине

### 1. Устаревший yt-dlp или extractor

Предложить пользователю обновить **вручную выбранный release-бинарник** через
`-U`/`--update-to nightly` либо показать команду для его способа установки.
Не запускать `brew`, `pip`, `pipx` или иной пакетный менеджер из приложения:
это меняет окружение и может обновить другой Python. После обновления повторить
один раз с прежней конфигурацией. Каналы и ограничения самообновления описаны
в [официальном README](https://github.com/yt-dlp/yt-dlp#update).

### 2. Вход, возрастное ограничение или CAPTCHA

Если пользователь **имеет законный доступ** к материалу в браузере, предложить
обновить страницу сервиса в этом браузере и выбрать его профиль для
`--cookies-from-browser`; yt-dlp поддерживает Chrome, Firefox, Safari и другие
перечисленные браузеры, а также отдельный Netscape cookies-файл через
`--cookies`. [README yt-dlp: cookies](https://github.com/yt-dlp/yt-dlp#filesystem-options)

Для Cloudflare FAQ yt-dlp отдельно предписывает свежие cookies браузера с того
же IP и актуальный User-Agent браузера. [FAQ yt-dlp: Cloudflare 403](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#im-getting-http-error-403-and-the-site-has-an-open-issue-on-the-tracker-thats-labeled-cloudflare-related-what-can-i-do)
Интерфейс должен показывать предупреждение, что cookies являются секретом: не
выводить их в консоль, не добавлять в текст конфигурации и не отправлять
внешним сервисам.

### 3. Антибот-защита и TLS/browser fingerprint

Если stderr явно называет Cloudflare anti-bot challenge, generic extractor
сам предлагает `--extractor-args "generic:impersonate"`; это следует
предлагать как разовую опцию для данного домена, а не включать глобально.
[Исходный код generic extractor](https://github.com/yt-dlp/yt-dlp/blob/master/yt_dlp/extractor/generic.py#L3690-L3723)

Также поддержан `--impersonate CLIENT[:OS]`, а доступные цели можно посмотреть
через `--list-impersonate-targets`. Для некоторых сайтов нужна зависимость
`curl_cffi`; официальный README предупреждает, что принудительная
имперсонация всех запросов может ухудшить скорость и стабильность.
[README yt-dlp: impersonation](https://github.com/yt-dlp/yt-dlp#impersonation)
[README yt-dlp: network options](https://github.com/yt-dlp/yt-dlp#network-options)

Не подставлять произвольные заголовки автоматически. `--add-headers` поддержан,
а `--user-agent` и `--referer` — его эквиваленты, поэтому UI может дать
пользователю явное поле для заголовка, только если он воспроизводит разрешённую
сессию сайта. [README yt-dlp: workarounds](https://github.com/yt-dlp/yt-dlp#workarounds)

### 4. YouTube: EJS и поддерживаемые extractor arguments

Для полного YouTube support yt-dlp рекомендует `yt-dlp-ejs` и поддерживаемый
JavaScript runtime; это не то же самое, что добавлять неподдерживаемый CLI-флаг
в конфиг. [README yt-dlp: dependencies](https://github.com/yt-dlp/yt-dlp#dependencies)
При установленном Deno или Bun официально поддержаны `--remote-components
ejs:npm` и `--remote-components ejs:github`; EJS должен обновляться вместе с
yt-dlp. [Wiki yt-dlp: EJS](https://github.com/yt-dlp/yt-dlp/wiki/ejs)

`--extractor-args` допустим только в синтаксисе и для extractor-ключей,
перечисленных yt-dlp. UI не должен выдавать случайный набор аргументов как
универсальное лекарство от 403; сначала показать конкретную рекомендацию из
stderr или документации соответствующего extractor.
[README yt-dlp: extractor arguments](https://github.com/yt-dlp/yt-dlp#extractor-arguments)

### 5. Ограничение частоты, временный отказ или истёкшая ссылка

Не превращать 403 в бесконечный retry. Для временных сбоев доступны конечные
`--retries`, `--fragment-retries` и управляемая пауза `--retry-sleep`; для
снижения нагрузки — `--sleep-requests` и интервалы перед скачиванием.
[README yt-dlp: download options](https://github.com/yt-dlp/yt-dlp#download-options)
[README yt-dlp: workarounds](https://github.com/yt-dlp/yt-dlp#workarounds)

Для 429/402 FAQ рекомендует сначала решить CAPTCHA в браузере, затем передать
cookies с тем же IP; при отсутствии CAPTCHA — обратиться к сервису или
использовать только уже разрешённый/whitelisted IP. [FAQ yt-dlp: 429/402](https://github.com/yt-dlp/yt-dlp/wiki/FAQ#http-error-429-too-many-requests-or-402-payment-required)

### 6. IP, VPN/proxy и регион

Показать пользователю текущий режим сети и дать безопасный A/B: повторить один
раз без прокси (`--proxy ""`) либо с его уже настроенным прокси. yt-dlp
официально поддерживает HTTP/HTTPS/SOCKS proxy, привязку к локальному IP и
принудительный IPv4/IPv6; `--force-ipv4` уместен как диагностический вариант,
когда конкретный маршрут IPv6 даёт отказ. [README yt-dlp: network options](https://github.com/yt-dlp/yt-dlp#network-options)

Для сайтов с геопроверкой у yt-dlp есть `--geo-verification-proxy`, но это
только механизм проверки IP, тогда как фактическая загрузка использует обычный
`--proxy`. Не предлагать его для обхода территориальных условий: если
пользователь не имеет права на просмотр из текущего региона, нужен понятный
доменный отказ. [README yt-dlp: geo-restriction](https://github.com/yt-dlp/yt-dlp#geo-restriction)

## Когда прекращать подбор и показать доменную ошибку

Не повторять автоматически и не предлагать обход, если stderr или страница
сервиса указывают на DRM, платный/подписочный доступ без учётной записи,
удалённый/приватный материал, возраст/регион без подтверждённого права,
CAPTCHA без интерактивно пройденной пользователем проверки либо явный запрет
сервиса. Сообщение должно содержать домен, краткую причину, исходный код 403,
ссылку на журнал и безопасные следующие действия: войти в сервис в браузере,
подтвердить право доступа, подождать или обратиться в поддержку сервиса.

Не следует отключать TLS-проверку (`--no-check-certificates`) или понижать
HTTPS до незашифрованного соединения (`--prefer-insecure`) ради 403: README
относит эти флаги к workaround, но они не доказывают право доступа и ослабляют
защиту соединения. [README yt-dlp: workarounds](https://github.com/yt-dlp/yt-dlp#workarounds)

## Предложение для Savvy

Для первого релиза достаточно классифицировать текст stderr в четыре
пользовательских действия: **обновить выбранный binary**, **обновить cookies**,
**снизить частоту и повторить позже**, **проверить сеть/войти в сервис**. Все
остальные случаи оставить как доменную ошибку с журналом. Изменения конфигурации
должны быть разовыми и видимыми в снимке запуска; не включать cookies,
impersonation, proxy, EJS remote components или extractor arguments глобально
без явного выбора пользователя.
